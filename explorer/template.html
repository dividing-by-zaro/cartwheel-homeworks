The expected flow from the code. A real model can choose differently, which is what the evals measure.

    Architecture

    Same question, same AI, same database. The difference is how the AI reaches the data.

    Original: simple tools

    The AI picks from a menu of small, single-purpose tools.

    Person asks a questionshopper, merchant, or support
    Server adds who they arerole, user id, store: never taken from the chat
    AI modelreads the prompt, picks a tool
    10 small toolseach one checks permissions and rules in code
    get_orderfind_orderlist_my_ordersget_refund_statussearch_productsget_policysearch_help_centerissue_refundcancel_orderescalate_to_human
    Databasestores, products, orders, refunds

    SQL: the AI writes queries

    The AI writes its own database queries through two tools.

    Person asks a questionshopper, merchant, or support
    Server adds who they arerole, user id, store: never taken from the chat
    AI modelreads the prompt, writes SQL
    read_sqlany SELECT query
    Private copyholds only this person's rows, rebuilt per query, read-only
    write_sql3 allowed statements
    Same checks as beforecancel, refund, escalate: permissions, $100 limit
    Databasestores, products, orders, refunds
    Fewer tools, more to know2 tools instead of 10, but the AI has to know the tables and write correct queries itself.
    Same safety rulesPermissions and money rules stay in code. The AI can't see or change data it isn't allowed to.
    Different failure signalsAn off-limits order returns "no rows" instead of "permission denied".

    What the model sees

    Every model call sends the system prompt plus the full definition of every tool the role can use. These are the exact definitions from the code, with token counts from the tokenizer. Conversation history and tool results come on top.
